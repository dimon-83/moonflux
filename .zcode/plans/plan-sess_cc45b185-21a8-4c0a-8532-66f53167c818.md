# mbel 自定义函数规范接入算子体系（P6：规则资产·函数集）

## 设计定调（依据调研事实与你的三个选择）

**信任边界 = 可信资产 + 预留沙箱路线**；**粒度 = 表达式内标量函数（函数集）+ 批记录算子（现状保持）**；**范围 = 方案 A 全量 + ABI v2 设计稿（只设计不实现）**。

三份事实依据（探针已确认）：
- mbel 表达式体函数：`Engine::add_expression_functions(UserFunctionDef{name,params,body})`，确定性（递归 256 上限、Vm 程序缓存、steps 预算内），**先注册再 `eval_expr_checked` 即可让 unknown-name 在发布期拦截**；JSON v1 载体格式已存在（name/params/body/description）。
- moonflux 现状：`apps/transform` 零自定义函数（仅 56 内建）；spec schema 无函数集位置；`compile_node` 是唯一编译入口。
- AGENTS §8 早已把"函数集"列为必须版本化的规则资产——本里程碑就是把这句话落地。

**与算子体系的关系（写进决策记录的核心论点）**：治理面同构——工件化（JSON 文档）、版本化（单调版本）、发布期校验（静态检查）、预算（mbel limits + 递归上限）、fail-closed（EvalError → 记录不放行）；区别只在运行时位置（宿主侧 mbel vs wasmtime 沙箱），由信任边界决定。不可信标量函数的终态是 ABI v2 标量调用（设计稿交付，不实现）。

## Tickets（`.scratch/moonflux-p6/issues/`，编号 36–39）

### 36 — 函数集资产与命令面
- `apps/cli/metadata.mbt`：`ClusterMetadata` 增 `function_sets : Array[FunctionSet]`，`FunctionSet{name, version, functions: Array[FunctionDef]}`，`FunctionDef{name, params: Array[String], body, description?}`（字段名与 mbel JSON v1 对齐）；`create/delete/list/get` 函数（版本单调、重名拒绝、原子写沿用）。
- 校验（发布期，全部结构化错误）：名字走 mbel 的标识符规则（非关键字/非聚合名/非 `$env`、集合内唯一）；params 唯一；body 非空；未知字段拒绝。**纯度检查**：body 与 params 中出现 `now`（及未来不确定性内建黑名单）→ 拒绝——决策依据：确定性重放是 AGENTS §5 红线，规则资产（表达式+函数体）统一适用；第一版为文本级 token 扫描（文档注明边界）。
- CLI：`function-set create --name N --file fns.json --remote <node>` / `list` / `get --name N` / `delete --name N`；协议加法命令 `CMD_FUNCTION_SET_CREATE/LIST/DELETE/GET = 22/23/24/25`（沿用 topic 动词的加法模式）。
- `serve`/`spu`（hub 的 `dispatch_session_frame`）与 sc 都接这组命令：**函数集是节点本地资产**（各自 metadata.json），集群内分发随 SC 的 spec 分发走（当前架构本就是逐节点 apply，文档注明）。

### 37 — spec 引用与编译链
- `core/spec`：`$.spec.functions`（可选，字符串 = 函数集名）；`reject_unknown_keys` 白名单补上该键。
- `apps/transform`：`compile_with(expr, functions)`（先 `add_expression_functions` 再静态检查再编译）；`compile(expr)` 保持 = 空函数集。**实现细节待验证**：优先用 mbel 公开的 JSON→UserFunctionDef 解析入口（playground 有 `eval_with_functions(funcs_json,…)`，说明解析器存在）；若不公开则在 apps/transform 侧用 core/json 构造 `UserFunctionDef`（字段公开性执行时确认）。
- `apps/cli/rules.mbt` `compile_node`：ExprTransform 编译前按 `spec.functions` 名字从本地 metadata store 解析函数集；**缺失或不可用 → apply 失败**（发布期）。`persist_applied` 存原 spec（引用不变），函数集**版本号写入 topology.json**（运维可见漂移）。
- 语义决策（写进 ticket 与决策记录）：**函数集更新需重新 apply 才生效**（热重载的版本戳是 topology.json mtime；资产版本独立演进，re-apply 绑定）——与"spec 是不可变部署"一致。
- 单测：静态检查解析自定义名（此前必失败的用例转为通过）、缺失集拒绝、纯度拒绝、mbel 预算对函数体生效（深递归被拦）。

### 38 — 门禁与决策记录
- `scripts/e2e-p6-functions.sh`：① `function-set create` 部署 + list 可见（版本单调）；② spec 引用集合 + 表达式调用自定义函数 → apply 成功 → run/consume 取回按函数变换的记录；③ 引用缺失集合 → apply 拒绝；④ 表达式用了集合外自定义名 → apply 拒绝；⑤ 函数体含 `now` → apply 拒绝（确定性理由）；⑥ 集合更新 + re-apply → 行为变化（版本可见）。纳入 `scripts/gates.sh`。

### 39 — ABI v2 标量调用设计稿 + P6 关账
- `docs/operator-abi-v2-scalar.md`（**只设计不实现**）：动机（不可信标量函数进沙箱）；形态 = ABI v1 的 7 个批导出保持不动 + **可选**标量导出 `mf_op_scalar_abi_version() -> Int`、`mf_op_eval(request: Bytes) -> Bytes`（request 首版 JSON `{"fn","args"}`，二进制编码列为开放问题）；宿主侧函数注册表 `{name → module, budget}`，mbel 宿主闭包 marshal `@ast.Value → JSON` 逐调用执行（fuel 逐调用安装）；错误 → EvalError → fail-closed；确定性由 guest 无导入结构性保证。开放问题清单：参数类型编码、错误分类、标量调用批量化、注册表治理。
- README 决策 31（ABI v2 设计稿定调：触发条件 = 不可信标量函数需求）；P6 关账提交。
