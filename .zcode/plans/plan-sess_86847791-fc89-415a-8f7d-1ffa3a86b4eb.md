# moonflux CLI 命令工具规划（纯文档，不改代码）

## 背景结论
moonflux 已有 CLI（`apps/cli`：`produce` / `consume` / `serve` / `pipeline plan|apply|run`，P0/P0′/P1 门禁全绿），但对照 Fluvio CLI overview（cluster start、topic create/list、produce、consume、partition list、cluster spu list、SmartModule、benchmark）存在成片缺口，且现有规划散落在 ticket 17 / AGENTS.md 决策 / 评估报告 §4.4.2、§6.4，**没有一份成体系的 CLI 命令面规划**。本次补齐该规划。

## 变更内容

### 1. 新建 `docs/cli-roadmap.md`（中文，沿用现有 docs 命名与风格）
结构：
- **现状**：4 个命令 + 3 个子命令的命令表、门禁脚本对应关系（`scripts/e2e-*.sh`）；
- **对标基准**：Fluvio CLI 命令面全表（来源：fluvio.io CLI overview + 评估报告 §2.x 各节，逐条标注依据章节）；
- **缺口 → 分阶段映射**（每条注明前置能力）：
  - **现在可做**（单分区文件布局已支持）：`topic create/list/delete/describe`、`consume` 起点/终点扩展（`-B`/`-T`/`--end`）、`profile` 连接管理（替代裸 `--remote`）、`pipeline delete`（§6.4 提议过）、codec 校验命令（复用 vectortool 能力，§4.4.2）、usage() 帮助补 `pipeline`；
  - **P2 随 ticket 17**：operator（≈SmartModule）注册/列出、consume 挂 operator；
  - **P3（控制面就绪后）**：`partition list`、`cluster spu list`、all-in-one / sc / spu 子命令拆分（AGENTS.md §1.2 决策）、`benchmark`；
  - **P4**：随跨语言 SDK 稳定化 CLI 契约；
- **勘误清单**（发现未修，供后续 ticket）：`usage()` 漏 `pipeline`；README 待办行与 P1 状态不同步；`core/spec` `.mbti` 待 `moon info` 重生成；
- **边界声明**：本规划不改变 P2 进行中的工作（wasm 算子优先），各批次在实际启动时再按惯例立 ticket。
