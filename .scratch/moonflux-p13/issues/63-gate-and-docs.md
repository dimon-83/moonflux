# 63 — 门禁 + 留痕

**What to build:** `scripts/e2e-p13-control-plane.sh`（5 条腿），纳入 `scripts/gates.sh`：

① **stalling 探针之下节点不被判离线**：3 个 spu 正常注册心跳，同时 6 个探测者"连上不发数据"（TCP 连上即停；
  TLS 端口下即发起握手后停在半途），在 ≥2 倍存活窗内断言 SC 日志**没有** `is offline` 行、且节点记录持续更新；
② **慢客户端不阻塞他人**：一个客户端发出半帧（长度头声明有载荷但只发一半）后停住，另一个客户端在同一窗口内
  发 `CMD_NODES` 并在**远小于旧路径所需时间**内拿到正确应答（断言的是"能拿到且正确"，时限用宽松上界，
   不让门禁变成机器负载的函数）；
③ **安全面回测**（改了调度不能把安全面改没）：无凭据 → `code 9`；客户端凭据发 `CMD_REGISTER` → `code 10`；
  错 CA → 握手失败；正确凭据 → 命令正常；
④ **真死仍判离线**（反例腿）：kill 一个节点 → 存活窗后 SC **必须**打出 offline 行（否则"不再误判"就成了
   "不再检测"）；
⑤ **多客户端并发命令各自正确**：≥4 个并发连接各自 `CMD_NODES`/`CMD_LEADER`，应答互不串线（rid 回显正确）。

### 关账（2026-09-17）

`scripts/e2e-p13-control-plane.sh` 五条腿全绿并纳入 `scripts/gates.sh`（**31 步**）。与票面设计的差异（都是
"执行时发现更好的判据"，留痕）：

- 控制面端口**开 TLS**：沉默对端只有在"有握手可停"时才昂贵，明文端口会让腿 1 因为错误的原因通过。
- 腿 1 的判据从"看起来还行"改成**三个症状计数器**（`is offline` / `leader of` / `offering`）前后不变——
  误判离线**本身就是**代价，而选举与提名是它留下的痕迹。为了让它有意义，门禁先真起一个 3 分区 topic
  （有数据才有水位、才有选举可误触发）。
- 腿 2 的时限用宽上界（<1s）而不是精确值：断言"没被拖住"，不是把机器负载写进门禁。
- 腿 4 是**反例腿**：kill 一个节点后必须仍然打出 offline——否则"不再误判"可能只是"不再检测"。
- 腿 5 用 TLS 全握手 + 认证的四个并发连接，各自核对应答内容（rid 回显之外，还要 payload 对得上）。

**门禁逼出的两个真 bug 见 ticket 64**（环状死锁与 SIGPIPE）——这条腿的价值不在于它绿，而在于它红的时候
指对了地方。
