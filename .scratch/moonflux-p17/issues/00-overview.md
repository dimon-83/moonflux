# 00 — P17 里程碑概览（benchmark 工具）

**门禁（可证伪）**：`scripts/e2e-p17-bench.sh` 全绿——吞吐/延迟数字**只报告**，门禁断言的
全是结构事实：计数与偏移区间精确、序号头校验通过、百分位单调（min ≤ p50 ≤ p90 ≤ p99 ≤ max）、
超限记录按名拒绝且服务端存活、整个基准期间服务端 `opened` 行**每分区恰好一条**（P16 回归护栏）。

**前置事实（对标与实测，设计据此）**
- 参考系统的 `fluvio benchmark` = **producer 吞吐 + 延迟直方图**（min/avg/max + p50/p95/p99），
  全参数矩阵（batch/linger/压缩/记录大小/生产者数/分区/副本），自动建删 topic；**consumer 基准
  隐藏未发布**（报告 §2.12）。moonflux 补上 consume 与 produce→consume 可见性两个模式——P16
  回归护栏需要读写两侧，且「复制代价不再 O(段长)」的动机要读写都有基线。
- `@env.now()` 只有毫秒——本地回环上 p50 会圆成 0，直方图失去意义。垫片加**单调微秒时钟**
  （`mf_cli_now_us`，CLOCK_MONOTONIC：测的是间隔，间隔不能随 NTP 跳）。
- 基准记录的值头 4 字节大端序号（= 记录偏移），是负载下最便宜的完整性检查——恰好钉住
  「应答基址错位」这一类 bug（P15 修过一个，这是下一只的绊线）。

**范围裁剪**：不做多生产者/linger/压缩矩阵（moonflux 无压缩；单 poll hub 上一条连接就是诚实
的第一基线）；不做 topic 生命周期（serve 尚无 `topic delete`——已知缺口，另有小票）；**墙钟
不进 pass/fail**（决策 33 的数据面推论，README 决策 41 留痕）。
