# 00 — P8 里程碑概览（存储完备：段滚动 · 稀疏索引 · retention）

**门禁（可证伪）**：一个分区的日志在滚动后由多个段组成——跨段读取与单段历史**字节/记录完全一致**；
索引 seek 与全扫同结果（索引损坏/缺失时回退全扫，绝不给出错误数据）；retention **只删整段**且**不越过**
给定的安全下界（已提交前缀与最慢消费者之间的较小者）；撕裂尾只影响最后一段；复制（`read_raw`）跨段仍
逐字节一致；运维面能看到每分区的段数与字节数。

**为什么是这一票**：README「待办」的下一里程碑候选第二项，也是 compatibility-matrix #10 剩下的那一半
（存储与数据路径就绪、逐分区复制已通，但**段滚动/稀疏索引/retention 未实现**）。今天 `SegmentedLog`
是**单文件**：`open`/`read`/`read_raw` 都把整个文件读进内存扫描，日志只会长不会收。

**范围**：内核多段日志（注入式段存储）+ 稀疏索引 + 滚动与 retention 策略（时钟注入）+ 运维面 + 门禁。
**不做**：压缩/compaction（另立）、跨分区的事务、索引的 mmap/二级缓存、K8s。

**Tickets（编号全局连续）**
- 44 多段日志与注入式段存储（`SegmentStore{open,list,remove}`；滚动发生在批边界；恢复只在最后一段）
- 45 稀疏索引（每段一份 offset→position 索引；损坏/缺失回退全扫；seek 与全扫同结果）
- 46 滚动与 retention 策略（大小/时间两种滚动；retention 只删整段且 `end_offset ≤ floor`；floor 由应用给出）
- 47 门禁 + 运维面 + 留痕（`scripts/e2e-p8-storage.sh`；`cluster segments`；矩阵 #10 收尾；README 决策 31）
