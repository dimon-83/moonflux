# 00 — P12 里程碑概览（安全面：认证 · 授权 · TLS）

**门禁（可证伪）**：节点开启认证后——**没有凭据的连接被结构化拒绝**（不是"连上但什么都不给做"）；
只读身份**不能**生产、不能删主题、不能改函数集（每一条都有断言）；坏 token 被拒且**比较是常数时间**；
节点间命令（注册/心跳/SYNC_*/确认）**只对节点身份开放**——今天任何人都能用 `CMD_REGISTER` 假冒节点、
用 `SYNC_ACK` 伪造水位（这是**完整性**漏洞，不只是访问控制）；TLS 开启后**无证书/错 CA 的握手失败**，
TLS 之下的复制仍然逐字节一致；**未配置认证时保持向后兼容**（所有既有门禁照常全绿，启动时**明说**正在无认证运行）。

**为什么是这一票**：安全面是目前唯一"完全没有"的能力面，它卡住任何真实部署。参考系统（对标）有 TLS +
x509 CN → 角色绑定（Root / ReadOnly / Basic）的 RBAC，以及 `flv-tls-proxy` 这样的 TLS 前置代理形态；
本里程碑按同样的语义面自建，并延续本项目既有纪律（能力可缺席的适配层、内核纯计算、发布期校验）。

**范围与顺序**：
- 56 内核鉴权语义（`core/auth`：身份/角色/命令权限表/常数时间比较；纯计算）
- 57 握手期认证（协议加法 `CMD_AUTH`；服务端先认证后服务；节点身份与客户端身份分开；CLI/节点凭据）
- 58 TLS 传输（`adapters/tls-native`：OpenSSL C shim + dlopen，能力可缺席；传输抽象升级 + hub/SyncLink 接入）
- 59 节点间安全（SPU↔SC 与复制链接同样认证 + TLS；否则内网即信任的假设会把安全面打穿）
- 60 门禁 + 留痕（`scripts/e2e-p12-security.sh`；矩阵新增安全行；README 决策 35；AGENTS §2）

**不做**：SASL/用户名密码体系（证书与 token 覆盖当前需求）、细粒度 ACL（按主题/分区的逐用户授权，
首版按角色）、证书轮转/OCSP、审计日志（列入后续候选）。
