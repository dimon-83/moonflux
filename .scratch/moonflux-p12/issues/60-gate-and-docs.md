**关键取舍：门禁用独立客户端取证**。第 5 腿要断言"客户端身份不能发节点命令"，而 moonflux CLI 根本不会发它
不认可的命令——用 CLI 断言就变成了"测 CLI 的克制"，不是"测服务端的授权"。于是写了
[`scripts/mfs_probe.py`](mfs_probe.py)：一个**独立实现**的 MFS 客户端（Python，自带帧编解码），
既能伪造任意命令，也是一次"从外部对协议第二次实现"的对拍。断言取**恰为 `code 10`**而不是"某个错误"：
权限判定发生在**解析载荷之前**，所以越权码本身就是"门还在"的证据，而载荷错误意味着门已经被打开。

**门禁自身的三次修正也留痕**（都是"断言写得比事实弱/宽"的典型）：① 只读那条腿先按 `code 10` 字面匹配，
漏掉了生产路径的 `Server(code=10, …)` 拼法——改成匹配**错误码**而非某种拼法；② "复制已结算"先写成
`hw=2 leo=2`，把腿的执行顺序当成了不变量（第 4 腿已经往 partition 0 写过一条）——改成 `hw == leo && hw >= 2`，
结算的含义与字面数字解耦；③ 伪造 REGISTER 的那条腿最初打在主集群上，而**被接受的**幽灵节点会真的进入副本集合
（HW = min(LEO) 停在 0）——移到第二个控制面上，让"证明角色边界"与"保持主集群干净"两件事互不干扰。
