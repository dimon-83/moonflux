# 00 — P14 里程碑概览（键语义与键控压实）

**门禁（可证伪）**：`scripts/e2e-p14-compaction.sh` 全绿——键从 produce 到 consume 全链路可见；
压实删除「已被更新版本取代」的记录并报告；**存活记录的偏移不变**（空洞可读）；
floor 之上永不动；leader 与 follower 各自压实后**逐段字节一致**；压实后重启恢复干净。

**前置事实（本轮实测，设计据此）**
- 键在协议与日志里已存在（`Record.key`，uleb128 长度 0 = 空），但 `produce` 与所有连接器
  硬编码空键——键语义从未启用（feature-matrix ⏳ 行）。
- **v2 批内偏移是「基址 + 序号」的位置语义**：`read`/`read_raw`/索引重建/段汇总/截断全部
  **靠数帧推偏移**（`core/log/log.mbt`）。因此**拆分批次即重编号**——记录偏移是身份
  （消费偏移、水位、截断都由它定义），绝不可重编号。
- 结论：**压实以「连续偏移段」为最小单位**：被淘汰的记录直接消失，存活的连续记录
  重新成帧（帧基址 = 该段首条存活记录的原始偏移）；读取路径改为**信任 `batch.base_offset`**
  并容忍帧间空洞。

**范围裁剪**：不做墓碑（v1 无 null 值语义，删除即丢帧——不引入新帧版本）；不做周期自动
压实（首期是显式命令，周期化留待需要）；不做批内分裂。
