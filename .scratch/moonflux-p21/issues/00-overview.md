# 00 — P21 里程碑概览（细粒度授权与审计日志）

**门禁（可证伪）**：`scripts/e2e-p12-security.sh` 新增腿 8–10 全绿——按主题 ACL 的**允许与拒绝**
双向（授权主题可读可写、未授权主题按名拒绝且错误码 10）、**无 grants 的凭据行为逐字节不变**
（回归）、**审计日志**记录拒绝与认证失败且**不含任何凭据材料**。

**定位**：这是生产就绪度评估（`docs/production-readiness.md` §3.4）点名的**唯一需要开发才能补的
缺口**——补上它，评估里"通用/对外/合规场景不可以"的结论中，合规面这一条解除（其余缺口是运维
面，见评估 §4 清单）。

**对标定位（诚实标注）**：参考系统的授权是三级策略（Root / ReadOnly / **Basic RBAC**——JSON
策略文件把 Role 绑到 ObjectType×Action，8 类对象，判定在 SC 管理面；报告 §2.11.1）。moonflux
本里程碑是**按主题的实例级授权**（比 ObjectType 粒度更细——主题是本项目的核心对象）+ **独立
审计流**（参考系统报告未列审计面）——**超出对标的自建能力**，判定位置也不同：moonflux 在
数据面分发入口（Fluvio 在 SC）。

**语义（先定死，再实现）**
- **角色表先行，授权收窄**：`permit(role, cmd)` 仍是第一道门（在解析载荷之前，P12 纪律不变）；
  `authorize_topic` 是第二道更窄的门——**只收窄、不放大**：read-only 角色即使带 write grant
  也不能写（角色表先拒绝）。
- **无 grants = 角色说了算**：不带 grants 的凭据行为与 P12 逐字节相同（回归腿钉住）。
- **Node 不受 ACL 约束**：复制是基础设施信任（P12：节点信任是另一种信任）。
- **审计 = 拒绝 + 认证失败 + 主题生命周期**，不是每条记录（量）；**凭据永不入审计**（P12 的
  grep 腿会盯着）。

**边界**：不做组命令的主题级检查（组成员按协调者的分配读，协议层不携带单主题判定点）；不做
SC 控制面声明类命令的 ACL（topic create/delete 是集群声明，沿用角色表）；不做 SASL/证书轮转。

**Tickets（依赖序）**
- 84 授权模型（core/auth：TopicGrant + authorize_topic + Identity/Credential 扩展 + wbtest）——无阻塞
- 85 配置、接线与审计（auth.json grants 解析校验 + 三处分发入口 + audit 写入器）——阻塞于 84
- 86 门禁与文档（e2e-p12 腿 8–10 + 全部文档同步）——阻塞于 85
