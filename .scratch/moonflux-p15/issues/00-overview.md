# 00 — P15 里程碑概览（载荷预算）

**门禁（可证伪）**：`scripts/e2e-p15-bulk.sh` 全绿——20 MiB 文件端到端逐字节一致；跨分块偏移精确；
超限记录按名字拒绝且服务端存活；超限帧被**报告**（而非静默重置）且服务端存活；12 MiB 批次复制逐字节一致。

**前置事实（本轮实测，设计据此）**
- 8.7 MiB 的 `produce` 被服务端**静默重置**（`connection reset`，服务端日志一行都没有）、10 MiB 的
  `consume` 被写一半丢弃（`peer is not reading`）——根因是一个自相矛盾的常量：协议解码器收 16 MiB
  批帧，hub 收发缓冲写死 8 MiB。**传输不得比协议更严格却不说**。
- 大批次复制**永不完成**：SYNC 应答是一帧、由 tick 驱动循环写出（每 poll 一轮），16 MiB 需要几十轮
  poll，长过 2s 对端期限——`hw` 停在 0 不是复制慢，是每轮都超期。
- 每读 8 KiB 泵一次连接，而每次泵值一个 50 ms poll tick：应答越大死得越确定（P7「泵必须贯穿等待」
  纪律的推论，本轮被再次踩实）。

**范围裁剪**：不做批压缩（feature-matrix ⏳）；不承诺批间原子（至少一次口径的推论）；单条超限不代为
切分（切分是应用语义，平台按名字拒绝）。
