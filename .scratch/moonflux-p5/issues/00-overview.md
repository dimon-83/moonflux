# 00 — P5 里程碑概览（并发连接 + 多分区 + 运维面）

**门禁（可证伪）**：**并发连接下服务不饿死任何人** —— 一个浏览器长连接 + 两个 CLI 客户端 + 一个
被挂起（不读不写）的连接同时存在时，每个健康客户端都能在秒级内得到应答；且被挂起的连接不会拖慢别人。

**为什么这是第一位**：P4 端到端门禁暴露的真问题——`serve` 一次只服务一个连接（P1 遗留），
浏览器的长连接会饿死 CLI 与所有其他客户端。这不是"性能优化"，是**可用性缺陷**：只要有第二个
客户端在场，第一个客户端的长连接就让集群看起来挂了。修法不是加线程，而是把服务循环改成
**事件驱动（poll 多连接）**——与"节点是单线程循环、定时做家务"的既有形态一致。

**Tickets（依赖序，编号全局连续）**
- 32 连接多路复用：`net-native` 非阻塞与 poll 原语 + `serve`/`spu`/`sc` 的事件循环（每连接状态机）
- 33 多分区存储：`<topic>/partition-N.log` + 生产/消费按分区 + 放置驱动的分区选择（索引/retention 仍留后）
- 34 算子管理 CLI：`operator list/verify/describe`（对 ABI v1 校验真实 .wasm，对标 SmartModule 命令面雏形）
- 35 P5 关账：并发门禁 + 文档 / 矩阵 / 决策记录

**范围裁剪**：不引入线程/async 运行时（内核红线与既有形态都不允许）；多分区不做跨分区事务性；
K8s 部署形态不在本里程碑（需 CRD 后端，另行立项）。
