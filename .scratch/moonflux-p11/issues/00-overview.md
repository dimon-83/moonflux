# 00 — P11 里程碑概览（控制面资产下发：spec 与函数集）

**门禁（可证伪）**：一条 spec **只在控制面 apply 一次**，集群里的数据节点各自拉取并运行——不需要逐节点
apply；一个函数集**只在控制面部署一次**，引用它的 spec 在每个节点上都能编译；新加入的节点自动拿到当前
修订（不需要人工补部署）；节点上已有更高修订时不回退；控制面不可达时节点**保留**手上的资产继续跑（不空转）。

**为什么是这一票**：集群里 `pipeline apply` 与 `function-set create` 目前都是**逐节点**的（每个 P3/P7/P9
门禁都对每个 spu 各做一次）——多节点使用的真实摩擦。它同时把 P6 遗留的"函数集集群分发"一并解决，并沿用
两条既有纪律：**SC 不主动拨号数据节点**（决策 20）→ 只能**节点拉取**；**状态随心跳应答下发**（决策 20/29）
→ 心跳只带修订号，文档在修订变化时按需拉取（几 KB 的文档不该每 500ms 走一趟）。

**Tickets（编号全局连续）**
- 52 控制面持有已应用的 spec（SC 校验 + 版本 + `CMD_PIPELINE_FETCH`；apply 到 SC 成为集群语义）
- 53 节点拉取与本地编译（心跳带修订 → 变化则拉文档 → 本地编译运行；节点不回退、离线不空转）
- 54 函数集随之下发（函数集在控制面创建 → 节点按需拉取；`function-set` 动词对 SC 与对节点两种口径都保留）
- 55 门禁 + 留痕（`scripts/e2e-p11-assets.sh`；README 决策 34；AGENTS §2）
