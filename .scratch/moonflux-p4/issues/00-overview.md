# 00 — P4 里程碑概览（全平台体验：SDK 完备 + Web 编辑器 + 部署形态）

**门禁（可证伪）**：端到端 —— **拖拽一条管道 → 运行 → 消费到数据**。
由真实浏览器驱动（headless 亦可），不接受"页面能打开"这种替代品；断言必须落在数据上：
编辑器产出的 spec 被内核接受、apply 后 serve 真的跑了这条管道、消费侧读到预期记录。

**与 P3 的关系（顺序理由）**：编辑器是 **spec 的渲染器**（决策 5/7），所以它必须建立在
"spec 单一真相 + 内核可编译到浏览器"之上；而浏览器里没有 raw TCP，客户端需要一条浏览器可用的
传输（WebSocket 网关）。因此 P4 的前三件是：**读钳制接线**（把 P3 已实现但未接线的读语义补齐，
否则"消费到数据"的语义是残缺的）→ **客户端内核化**（帧编解码/客户端逻辑编译到 wasm-gc）→
**WS 网关**（浏览器传输）→ **编辑器**（渲染 spec 并驱动 apply/run/consume）。

**Tickets（依赖序，编号全局连续）**
- 27 读语义接线：COMMITTED 读命令 + `consume --committed`（关闭矩阵 #11 的客户端半边）
- 28 客户端内核化：纯客户端包（帧编解码 + Producer/Consumer 逻辑，全后端可编译）+ 原生传输不变
- 29 WS 网关：`serve --ws`（浏览器传输，帧协议不变）
- 30 Web 编辑器 v1：spec 拖拽渲染 + plan/apply/run/consume（wasm-gc 编译内核）
- 31 P4 关账：浏览器驱动的端到端门禁 + 文档 / 矩阵 / 决策记录

**范围裁剪**：不做 K8s 部署（P4 可选项，且需 CRD 后端，另行立项）；编辑器不做多用户协作与
持久化工程（v1 是单页 + 内存态 + 本地存储）；多分区存储与算子管理 CLI 仍属 P3 尾巴，不塞进
本里程碑的门禁路径。
