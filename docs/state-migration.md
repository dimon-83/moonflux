# 有状态管道的跨节点迁移与续算（P36）

> **一句话**：状态是**键控主题**，所以它随复制走；续算靠状态主题里的**进度标记**；
> 而状态**写**必须走集群的 leader——一个分区在节点上**只有一个写入者**。

## 1. 机制

三件事拼起来，才让"有状态管道随分区迁移/重启续算"成立：

| 组成 | 是什么 | 为什么必须这样 |
| :--- | :--- | :--- |
| **状态 = 键控主题** | `spec.state.topic` 是一条普通主题（键控、可压实） | 复制、压实、floor、恢复全部复用既有四件事；"每键最新"就是压实的语义（决策 60/61） |
| **进度标记** | 状态主题里一个保留键 `__moonflux_progress__`，值 = **状态已折算到的下一个输入偏移**；**只在 `--resume` 时写** | 状态本身只回答"是什么"，不回答"到哪儿了"；续算要的就是第二个答案。它是"续算"的记账，所以没要过连续性的运行**不得**给用户的状态主题加键（案例门禁实测） |
| **写入走集群** | `pipeline run --state-remote <sc>`：状态写解析状态主题的 leader 后经 produce 落盘 | 节点数据目录的每个分区**只有一个写入者**（P16）。管道进程直接写同一个日志会让节点的缓存句柄变旧、`leo` 永远报 0，副本于是永远"已追平"（实测） |

### 一次批 = 一次 append

`StateContext::stage` 把本批所有状态节点的写**暂存到视图**（同批后面的节点因此看得见），
`commit` 在批末**一次 append**：本批的状态项 + 进度标记在同一帧里。

- 崩在 append 之前 → 整批丢失，`--resume` 会重读它；
- 崩在 append 之后 → 什么都丢不了。

这就是这套机制能诚实声称的边界：**不是事务日志，而是一帧之内自洽**。门禁腿 3 断言
本批的键与标记**偏移连续**（0..4），把"同一帧"变成可证伪的事实。

> 顺带修掉一个真缺口：此前链上每个状态节点**各自 append**，两个状态节点的链在两次
> append 之间崩溃就会留下半批状态——与"每批是一次事务"（决策 60）矛盾的正是这个。

## 2. 用法

```bash
# 第一次：说"我要连续性"——此时状态主题里还没有标记，它按声明的 from 开始并从此记账
$EXE pipeline run --data-dir <node-A 的目录> --spec count.json --state-remote <sc 地址> --resume

# 在另一个节点上续算：从状态记录的偏移继续（同一个 --resume，同一份语义）
$EXE pipeline run --data-dir <node-B 的目录> --spec count.json --state-remote <sc 地址> --resume
```

`--resume` 的日志（**stderr**）会说清它读到什么：

- `resuming at the offset the state recorded: 4 (the spec says from=beginning)` —— 接着算；
- `the state topic holds no progress marker yet; starting at the declared from=beginning` —— 首次运行。

**三条按名拒绝**（门禁腿 7）：文件/HTTP/stdin 源 + `--resume`（没有偏移可记）、
没有状态主题 + `--resume`（标记无处可读）、算子占用保留键（一个状态键有两种含义
就等于没有含义）。

## 3. 如实边界（不假装的部分）

1. **副本新鲜度决定正确性**。`--resume` 读的是**本节点状态副本**里的标记；副本落后于
   leader 时，标记更旧，已折算过的记录会被**再算一遍**。门禁断言的是副本已收敛
   （状态主题在本地有全部条目）的情形。生产上的做法：让管道在同一分区的 leader 上跑，
   或先等副本追平。
2. **`--state-remote` 是必需的，不是优化**。不加它，管道进程直接写本地状态日志 →
   节点的缓存句柄变旧 → 状态**不会复制**（这正是修这个问题时实测到的现象）。单机、
   单进程、无集群时直接本地写是安全的（那也是案例 15/16/17/23/25 的用法）。
3. **没有跨节点的状态再均衡**（把某个键从一个节点搬到另一个）。有状态管道是**进程**：
   它跟随的是它所在节点上的副本；"迁移"= 在另一个节点上重启并 `--resume`。把键空间
   在多个运行实例之间切分（每实例负责一部分键）没有做，也没有假装。
4. **进度是"输入偏移"，不是"恰好一次"**。至少一次仍是全局口径（决策 32）；这个标记
   把"重启后会不会重复折算同一批"从"会"变成"不会"，但它不是分布式事务。
5. **保留键在状态命名空间里**（`__moonflux_progress__`）。算子返回同名状态键会被按名
   拒绝；数据记录的键不受影响（那是另一个命名空间）。

| 腿 | 断言 |
