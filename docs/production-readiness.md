# moonflux 生产就绪度评估（快照）

> **定位**：对当前快照（P0–P18）的**生产就绪度评估**——分级结论、支撑证据、会变成事故的缺口、以及不开发新功能即可执行的最小生产化清单。**规约依据**：AGENTS.md §10（证据与状态规范）；**边界声明**：本文是**评估**，不是能力承诺——能力状态的单一真相在 [`feature-matrix.md`](feature-matrix.md)，对标语义在 [`compatibility-matrix.md`](compatibility-matrix.md)，进度在 [`project-roadmap.md`](project-roadmap.md) 与 [`progress-board.md`](progress-board.md)。结论只对文末「评估方法与局限」列出的证据范围成立；未做的验证（压载 / 长稳 / Linux）不在此承诺。
>
> **日期**：2026-09-23 · 评估对象：P0–P19（门禁 36 步绿，native 239 / wasm-gc 162）

## 1. 分级结论

- **受控场景下可以**（内部管线、单机房、受信网络、有人看护、RF≥2）：数据面的正确性与耐久性证据是完整的——应答前落盘、逐帧 CRC、撕裂尾截断恢复、复制逐字节一致、故障注入门禁全绿、至少一次语义无缺口。可以把数据托付给它。
- **通用/对外/合规场景不可以**：缺口集中在**运维面与工程面**（控制面单点、无可观测端点、Linux 从未验证、无发布工程），以及**一项开发缺口**（细粒度授权与审计）。其中大部分是部署与流程工作，不是功能开发。
- **一句话**：它现在能替你**保住数据**，但还不能替你**值夜班**。

## 3. 会变成事故的缺口（不开发功能就一直在）

1. **控制面单点**（最大风险）：SC 单进程、元数据单文件（`metadata.json`），无 HA、无备份/恢复工具。SC 宕机 = 消费组冻结、无新提名、无法建主题（**数据面继续服务**，P11 有腿证实）；SC 磁盘损坏 = 主题声明永久丢失。
2. **平台与工程面**：无 CI、无远端仓库；**Linux 从未验证**（开发与门禁全在 macOS）；唯一产物是 debug 构建；无版本/打包/安装/升级面，滚动升级未测。
3. **可观测性**：无 metrics、无健康端点——监控只能刮日志、用 CLI 轮询（`group describe` / `cluster offsets`）。
4. **合规面（唯一需要开发的缺口）**：四角色为粗粒度；**无按主题/用户的 ACL、无审计日志、无证书轮转**。
5. **容量与成本**：单线程每进程（容量按主题/节点手工切分）；无批压缩（磁盘/网络成本数倍）；单机 `serve` 恒 RF=1，**不能当生产数据面**（生产须 `sc` + `spu`，RF≥2）。
6. **平台细节**：macOS 的 `fsync` 只到驱动缓存（`F_FULLFSYNC` 才是真落盘）——"ack 即落盘"完整成立的前提是 Linux，而 Linux 恰好未验证（回到第 2 条）。
7. **运维手工性**：无 K8s operator / systemd 单元；压实需显式触发；无优雅退出（但 kill 是安全的——恢复语义兜底，门禁每天在杀）。

## 4. 最小生产化清单（不开新功能，配置与运维可补）

- [ ] 拓扑：`sc` + ≥2×`spu`，RF=2；**不用**单机 `serve` 承载生产数据
- [ ] 安全：`auth.json`（TLS + token）+ 角色分离（写/Root 最小化）；网络边界隔离
- [ ] 备份：定期快照 SC 的 data dir（一个 `metadata.json`）；接受"SC 挂掉期间协调面短暂停"
- [ ] 看护：外部编排（systemd/容器）+ 日志采集；用 CLI 轮询做消费滞后与水位探针
- [ ] 调优：按负载调大生产批（吞吐 ↔ fsync 成本）
- [ ] 已知接受项（书面化）：无压缩、无细粒度 ACL/审计、组随 SC 停机冻结、升级 = 停机重启（同版本协议 v2）

## 5. 评估方法与局限

- **已做**：通读耐久性关键路径（`core/log` 的 append/flush/恢复/压实）；结论逐条回链门禁腿或实测（P17/P18 的基准与洞实验）；对平台级事实（fsync 语义、无端点、无信号处理）做了源码核对。
- **未做（不在此承诺）**：压载与长稳（无 soak/longevity 测试）、混载下的延迟抖动分布、Linux/生产内核上的完整门禁、跨版本升级、磁盘满 / fd 耗尽 / 时钟回拨等极端场景的注入。
- **使用方式**：把本评估当**上线评审的输入清单**，不要当通过证书；每轮里程碑收口后复核（与 [`progress-board.md`](progress-board.md) 同步）。
